VERSÃO 0.3.0 - [Data: 2025-01-XX]
================================================================================

RESUMO DA VERSÃO:
- Refatoração completa: renomeado para PackPanel com nova identidade visual
- Adicionada página de configurações no wp-admin com abas Estilo e Conexão
- Implementado sistema de estilos dinâmicos via CSS variables
- Preparada integração com webhooks externos (GET JSON)
- Adicionado badge WhatsApp com detecção configurável
- Corrigido uso obsoleto de cupons (get_used_coupons → get_coupon_codes)
- Criada classe de debug encapsulada (PPWOO_Debug)
- Gerado contrato de campos para integração externa

--------------------------------------------------------------------------------
FUNCIONALIDADES ADICIONADAS:
--------------------------------------------------------------------------------

1. MENU PACKPANEL NO WP-ADMIN
   - Arquivo: inc/admin/class-admin-menu.php
   - Descrição: Novo menu "PackPanel" no wp-admin com interface de abas
   - Funcionalidades:
     * Aba "Estilo": Configurações visuais do painel
     * Aba "Conexão": Configuração e teste de webhook
     * UI no padrão WordPress (nav-tab-wrapper)

2. CONFIGURAÇÕES DE ESTILO
   - Arquivo: inc/core/class-style.php, inc/admin/class-admin-style-tab.php
   - Descrição: Sistema completo de personalização visual
   - Opções disponíveis:
     * Cor do texto
     * Cor do fundo do cabeçalho
     * Tamanho da fonte do título
     * Tamanho da fonte das informações
     * Espessura da fonte
     * Cor da tag WhatsApp
     * Cores das etapas (step1/step2)
   - Armazenamento: Option única (ppwoo_style_settings)
   - Aplicação: CSS dinâmico via wp_add_inline_style com CSS variables

3. CONFIGURAÇÃO DE WEBHOOK
   - Arquivo: inc/admin/class-admin-connection-tab.php
   - Descrição: Gerenciamento de URL do webhook
   - Funcionalidades:
     * Campo para configurar URL do webhook
     * Botão "Testar Webhook" com AJAX
     * Exibe status, latência e preview da resposta
     * Validação de URL e sanitização

4. CLIENT DE WEBHOOK
   - Arquivo: inc/integrations/class-webhook-client.php
   - Descrição: Classe para fazer requisições GET JSON ao webhook
   - Funcionalidades:
     * Método fetch() para requisições genéricas
     * Método fetch_external_orders() para buscar pedidos externos
     * Logs de debug integrados
     * Tratamento de erros e timeouts

5. BADGE WHATSAPP
   - Arquivo: templates/painel.php, inc/core/class-utils.php, assets/css/panel.css
   - Descrição: Badge visual para identificar pedidos do WhatsApp
   - Funcionalidades:
     * Badge compacto com border-radius e contraste
     * Detecção via meta _ppwoo_channel (WooCommerce)
     * Detecção via campo channel/source (pedidos externos)
     * Filtro aplicável: ppwoo_is_whatsapp_order
     * Cor customizável via configurações de estilo

6. CLASSE DE DEBUG
   - Arquivo: inc/core/class-debug.php
   - Descrição: Sistema encapsulado de logging
   - Métodos:
     * info(): Log de informação
     * warn(): Log de aviso
     * error(): Log de erro
     * timed(): Log com tempo de execução
   - Características:
     * Prefixo único: "PPWOO:"
     * Respeita PPWOO_Config::is_debug()
     * Integrado em todos os novos fluxos

7. CONTRATO DE CAMPOS
   - Arquivo: external-order-contract.txt
   - Descrição: Documentação completa dos campos usados pelo painel
   - Conteúdo:
     * Lista de todos os campos WooCommerce lidos
     * Meta campos customizados
     * Sugestões de chaves JSON para webhook
     * Estrutura detalhada de `shipping_methods` (method_title/method_id/total)
     * Regra atual de separação por aba (Motoboy vs Correios): status + `shipping_methods[0].method_title` contém "motoboy" (case-insensitive)
     * Exemplos de payload para Motoboy, Correios e Correios sem método de envio
     * Estrutura JSON sugerida
     * Notas importantes sobre formato

1. DETECÇÃO DO WOOCOMMERCE (BUGFIX)
   - Arquivo: inc/class-packing-panel.php
   - Problema: Em alguns ambientes/ordens de carregamento, `class_exists('WooCommerce')`
              pode retornar false mesmo com WooCommerce ativo, bloqueando o painel.
   - Solução: Implementado helper `is_woocommerce_active()` com múltiplos checks:
     * function_exists('WC')
     * class_exists('WooCommerce')
     * class_exists('Automattic\\WooCommerce\\Plugin')
     * is_plugin_active('woocommerce/woocommerce.php') quando disponível
   - Impacto: Reduz falsos “WooCommerce não encontrado” nos logs e libera o painel quando o Woo está ativo.

     * Verifica se tag já existe antes de criar
